# Reproducible Builds and Supply Chain Security

This document describes how to verify that build artifacts (WASM binaries, Docker images, npm packages, PyPI packages) match the source code in this repository, and how the chain of custody is attested using SLSA Level 3, in-toto provenance, Sigstore/cosign signatures, and SBOMs.

## Trust Model

Reproducible builds and supply chain security ensure that:
1. The deployed artifact was built from the exact source code in the repository
2. No intermediate modifications occurred during compilation or packaging
3. The build was performed on a hardened, ephemeral runner with a signed provenance attestation
4. Auditors can independently verify artifact integrity and origin

## Prerequisites

- Rust toolchain (1.80.0)
- Node.js 20.x + pnpm 9.x
- Python 3.12 + poetry 1.8.x
- Docker (recommended for bit-by-bit reproducibility)
- cosign 2.2.x (for signature verification)
- syft (for SBOM generation/verification)
- gh (GitHub CLI)

## Build Environment

To ensure reproducible builds, we pin exact versions and use hermetic build containers:

```bash
rustup install 1.80.0
rustup target add wasm32-unknown-unknown
```

The canonical build environment is defined in `docker/wasm.Dockerfile` and `.github/workflows/reproducible-build.yml`.

## Build Instructions

### Local Build (Native)

```bash
# Clean any previous builds
cargo clean

# Build with exact settings
cargo build --target wasm32-unknown-unknown --release \
  --locked
```

### Docker Build (Recommended)

  Using Docker ensures bit-by-bit reproducibility across systems:

```bash
# Build using the provided Dockerfile
docker build -f docker/wasm.Dockerfile -t audit-ledger:build .

# Extract the WASM from the image
docker run --rm -v $(pwd)/target:/out audit-ledger:Build \
  cp target/wasm32-unknown-unknown/release/audit_ledger.wasm /out/
```

## Verify WASM Binary

### Compute SHA-256

After building, compute the SHA-256 hash of the WASM binary:

```bash
sha256sum target/wasm32-unknown-unknown/release/audit_ledger.wasm
```

This produces output like:
```
abc123def456... target/wasm32-unknown-unknown/release/audit_ledger.wasm
```

### Compare Against Published Hash

Find the published hash for your release in one of these places:

1. **GitHub Releases** — Check the release notes for the associated commit tag
2. **CI Artifacts** — View GitHub Actions workflow logs
3. **Contract Deployment Record** — Check the deployment logs for the network (testnet/mainnet)

```bash
# Example: verify against published hash
PUBLISHED_HASH="abc123def456..."
COMPUTED_HASH=$(sha256sum target/wasm32-unknown-unknown/release/audit_ledger.wasm | cut -d' ' -f1)

if [ "$PUBLISHED_HASH" = "$COMPUTED_HASH" ]; then
  echo "✓ WASM binary matches published hash"
else
  echo "✗ WASM binary DOES NOT match"
  echo "Published: $PUBLISHED_HASH"
  echo "Computed:  $COMPUTED_HASH"
  exit 1
fi
```

## Verify Signatures (Sigstore / cosign)

All release artifacts are signed with Sigstore using keyless signing backed by GitHub Actions OID. To verify:

```bash
cosign verify-blob \
  --certificate-identity-regex '^https://github.com/daddygokings-art/Decentralized-Audit-Transparency-Ledger/.github/workflows/reproducible-build.yml@refs/heads/.*$' \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com \
  audit_ledger.wasm.sig \
  audit_ledger.wasm
```

For container images:

```bash
cosign verify \
  --certificate-identity-regex '^https://github.com/daddygokings-art/Decentralized-Audit-Transparency-Ledger/.github/workflows/reproducible-build.yml@refs/heads/.*$' \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com \
  ghcr.io/daddygokings-art/audit-ledger:<sha>
```

## Verify Provenance (in-toto / SLSA)

Provenance attestations are generated by the `reproducible-build` workflow and stored as `.attestation.jsonl` artifacts. Verify with the SLSA verifier:

```bash
gh release download <release-tag> --dir ./release
cd release
slsa-verifier verify-artifact \
  --source-uri git+https://github.com/daddygokings-art/Decentralized-Audit-Transparency-Ledger@git+refs/tags/<release-tag> \
  --provenance-path audit_ledger.wasm.attestation.jsonl \
  --artifact-path audit_ledger.wasm
```

## Verify SBOM

Every release includes SPDX 2.3 or CycloneDX 1.5 SBOMs. To validate:

```bash
# SPDX
syft spdx validate --file sbom.spdx.json

# CycloneDX
syft cyclonedx validate --file sbom.cyclonedx.json
```

To check that a given dependency is listed in the SBOM:

```bash
jq '.components[] | select(.name == "soroban-sdk")' sbom.cyclonedx.json
```

## Dependency Verification

Before building, run the dependency audits locally:

```bash
# Rust
cargo install cargo-audit cargo-deny --locked
cargo audit
cargo deny check

# Node.js
pnpm audit --audit-level high

# Python
pip-audit
poetry export --format requirements.txt --without-hashes > requirements.txt
pip-audit -r requirements.txt
```

## CI Integration

The CI/CD pipeline automatically:

1. Builds all artifacts in hermetic Docker containers
2. Computes SHA-256 hashes for every artifact
3. Generates in-toto provenance attestations
4. Signs artifacts with Sigstore/cosign
5. Generates SPDX and CycloneDX SBOMs
6. Publishes all artifacts, signatures, attestations, and SBOMs to the GitHub Release

### View Published Hashes

```bash
# Download artifacts from GitHub Actions
gh run list --repo daddygokings-art/Decentralized-Audit-Transparency-Ledger
gh run download <RUN_ID> -n wasm-sha256
cat wasm-sha256.txt
```

## Troubleshooting

### Hash Mismatch

If your computed hash doesn't match the published hash:

1. **Verify Rust version**
   ```bash
   rustc --version
   cargo --version
   ```

2. **Check for uncommitted changes**
   ```bash
   git status
   ```

3. **Ensure exact dependencies**
   ```bash
   cargo update --frozen
   ```

4. **Rebuild in Docker** (most reliable)
   ```bash
   docker build -f docker/wasm.Dockerfile -t audit-ledger:build .
   ```

### Binary Size Differs

If the WASM binary size differs significantly:
- Check the Rust version (affects codegen)
- Verify compiler flags in `Cargo.toml`
- Ensure LTO and optimization settings match

## Security Considerations

1. **Always verify hashes** — Never trust a deployment without verifying the WASM hash
2. **Verify signatures** — Cosign verification confirms the artifact was built by this repository's workflow
3. **Verify provenance** — In-toto attestations confirm the build parameters and inputs
4. **Use multiple sources** — Cross-check published hashes from GitHub, CI, and deployment records
5. **Audit the source** — Review the source code corresponding to the tag/commit
6. **Independent verification** — If possible, rebuild locally and compare
